# 浆果病虫害数据标注规范（YOLO）

## 1. 文档目的
- 为本项目提供统一、可复现、可质检的数据标注标准。
- 目标任务：目标检测（YOLO 格式），类别为：
  - `0: powdery_mildew`（白粉病）
  - `1: aphid`（蚜虫）
  - `2: gray_mold`（灰霉病）

## 2. 适用范围
- 数据来源：田间拍摄、温室拍摄、手机图片、相机图片。
- 适用模型：YOLOv8/YOLO11 等 YOLO 系列检测模型。
- 适用文件结构：`images/{train,val,test}` + `labels/{train,val,test}`。

---

## 3. 标注总原则（必须遵守）
1. 只标“看得清、能确认”的病灶或虫群。
2. 框尽量贴合目标外边界，不要过大包含太多背景。
3. 同一类型多个病灶可多框。
4. 模糊、强遮挡、严重反光无法判断时不标。
5. 类别判断有疑问时，先打 `疑难` 标签进复核清单，不要硬标。

---

## 4. Step-by-Step 标注流程

### Step 0：准备环境
1. 安装并打开标注工具（推荐 LabelImg、CVAT 或 Label Studio）。
2. 确认导出格式为 `YOLO txt`。
3. 在本项目建立目录：
   - `data/processed/berry_detection/images/train`
   - `data/processed/berry_detection/images/val`
   - `data/processed/berry_detection/images/test`
   - `data/processed/berry_detection/labels/train`
   - `data/processed/berry_detection/labels/val`
   - `data/processed/berry_detection/labels/test`

### Step 1：筛图（先选可用图，再标）
1. 删除重复图、过曝图、严重模糊图。
2. 每类优先保留清晰图，再补复杂场景图。
3. 建议比例：
   - 清晰标准图 60%
   - 复杂光照/遮挡图 30%
   - 边界困难图 10%

### Step 2：建立类目（class）
在标注工具中仅保留 3 个类别：
1. `powdery_mildew`
2. `aphid`
3. `gray_mold`

不要新增临时类名（例如 `mold`、`powder`、`bug`）。类名必须完全一致。

### Step 3：逐图标注
对每一张图按以下顺序执行：
1. 先看全图，判断是否存在目标类别。
2. 如果有目标，框出每个目标区域。
3. 调整框边界，确保紧贴目标。
4. 为每个框选择正确类别。
5. 保存标签文件。

### Step 4：自检（每张图标后立即）
1. 框是否覆盖目标主体？
2. 框是否过大包含大量背景？
3. 类别是否选错？
4. 是否漏标明显目标？
5. 文件名是否与图片一一对应？

### Step 5：批量复检（每天结束前）
1. 抽样 20% 图片做二次复核。
2. 统计问题：错类、漏标、框偏大、框偏小。
3. 记录到 `复核清单`（建议 CSV 或 Markdown 表格）。
4. 修正后再导出最终标签。

## 5. 各类别判定标准（细化）

### 5.1 powdery_mildew（白粉病）
**判定要点**
1. 叶面或叶背出现白色粉状/霜状覆盖物。
2. 可伴随卷叶、黄化，但核心证据是“白粉层”。

**怎么框**
1. 优先框白粉密集区域。
2. 若白粉分散，按连通区域分多个框。
3. 不要把整片叶子都框住，除非整叶几乎全被覆盖。

### 5.2 aphid（蚜虫）
**判定要点**
1. 叶背、新梢、花序附近出现成群小虫。
2. 常伴随蜜露、煤污，重点仍是虫体聚集。

**怎么框**
1. 框虫群，不框整枝条。
2. 多簇虫群分多个框。
3. 虫体特别小但可辨识时，可适当放宽框边距。

### 5.3 gray_mold（灰霉病）
**判定要点**
1. 花器、果实、叶片上出现灰色霉层/霉絮。
2. 往往与潮湿环境相关，病部软腐。

**怎么框**
1. 框霉层及相邻明显病斑。
2. 若病斑离散分布，分框标注。
3. 不要把健康组织大面积纳入框。

## 6. YOLO 标签格式规范

每个标签文件与图片同名，例如：
- 图片：`abc.jpg`
- 标签：`abc.txt`

每一行格式：
```text
class_id x_center y_center width height
```

要求：
1. 坐标全部为归一化值（0~1）。
2. 使用空格分隔。
3. 一个框一行。
4. 无目标图片允许空文件（建议保留空 txt）。

示例：
```text
0 0.512500 0.436111 0.281250 0.233333
1 0.223438 0.701389 0.106250 0.122222
```

## 7. 文件命名与版本管理规范

### 7.1 图片命名
建议：
```text
crop_class_scene_light_index.jpg
```
示例：
```text
strawberry_powdery_mildew_leaf_backlight_001.jpg
```

### 7.2 数据集版本
建议目录：
```text
data/processed/datasets/
  berry_v1/
  berry_v2/
```
每次大改（新增样本、重标）升一个版本，记录变更说明。

---

## 8. 训练集划分规范
1. 推荐比例：`train:val:test = 7:2:1`。
2. 同一株/同一连拍尽量不要跨集合，避免数据泄漏。
3. 各类别在 train 和 val 中都要出现。
4. test 集尽量保留“未参与调参”的真实场景图。

---

## 9. 质量控制（QA）检查清单

### 9.1 标注员自检清单
1. 是否漏标？
2. 是否错类？
3. 框是否过大/过小？
4. 是否把背景病斑当目标？
5. 类名是否统一？

### 9.2 复核员清单
1. 每类随机抽样至少 20 张。
2. 计算错标率和漏标率。
3. 错标率 > 5% 时整批返工。
4. 难例单独汇总形成“疑难库”。

### 9.3 数据完整性脚本检查（建议）
应检查：
1. 图片与标签一一对应。
2. 标签行数格式正确。
3. `class_id` 是否只在 `{0,1,2}`。
4. 坐标值是否在 `(0,1]` 范围内。

---

## 10. 常见错误与修正建议

1. **错误：整叶大框**
- 影响：模型学到背景，泛化差。
- 修正：只框病灶主体或虫群。

2. **错误：类名混乱**
- 影响：训练时类别映射错乱。
- 修正：统一为 `powdery_mildew/aphid/gray_mold`。

3. **错误：漏标小目标**
- 影响：召回率低。
- 修正：放大视图逐区检查，必要时多人复核。

4. **错误：困难样本全删**
- 影响：模型只会“理想场景”。
- 修正：保留一定比例难样本（10%~20%）。

---

## 11. 最小可演示数据建议（当前项目）
1. 每类至少 3 张真实标注，共 9 张。
2. 先训练 20~40 epoch 做定向演示。
3. 演示时降低阈值：
   - `YOLO_CONF=0.001`
   - `YOLO_BUSINESS_CONF=0.01~0.05`
4. 请求中带 `disease_hint` 提升检索稳定性。
